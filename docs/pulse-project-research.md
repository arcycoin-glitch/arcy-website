# Pulse V3 autonomous news

Each network's existing three slots show **ACHIEVED**, **UPCOMING**, and **RISK ALERT**, in that order. The current view reads `/api/pulse?view=projects&chain=…` using schema 2. Weekly editions, signed source inventories, numbered archives, ARCY Take, and the on-chain checkpoint path remain independent of the news feed.

## Discovery and evidence

The scanner polls a bounded registry of first-party feeds and indexes. It discovers item URLs at run time. The registry contains source and publisher identities, chain scope, and URL constraints. It contains no story titles, dates, or article URLs. An Aave forum topic requires a verified first post from a reviewed organization account. An Arc article requires its original displayed dateline. Related stories and navigation are excluded from the accepted evidence. Reuse of Arc and Ethereum parsing helpers does not add sources to the weekly signing inventory.

- **Achieved** uses attributable completed changes, stable software releases or relevant landed code. The evidence grade distinguishes those cases. Publication alone establishes what was reported.
- **Upcoming** requires a scoped, forward-looking claim or a structured maintenance schedule. A date-only target is labeled by day. Explicit timestamps retain UTC precision. A closed target is withheld without completion evidence.
- **Risk alert** requires a structured, dated publisher advisory or an incident affecting the reviewed mainnet scope. It includes the reporter's status and reference where provided. Generic ownership, admin or role changes do not qualify. Independent on-chain risk publication remains unsupported because the existing checkpoint's matching blocks and state reads do not establish cross-provider agreement for an incident. The new scanner makes zero RPC calls and does not change checkpoint freshness or freshness gates.

The evaluator rejects unrelated, undated, expired, future-published, contradictory and ambiguous items. Developments expire after 28 days and advisories after 14 days. Ranking considers evidence class, plan status, corroboration and recency. Stable incident references and near-identical headlines are deduplicated within a chain. Similar wording alone does not count as corroboration. Slot selection favors distinct projects while preserving the three categories. Missing evidence yields a specific slot status. The absence of an alert is limited to reviewed sources and provides no safety assurance.

## Refresh and bounds

The existing Railway Pulse worker loop reserves a cohort **once per 15 minutes** on its signed persistent volume and normally starts it on the next worker tick. Its separate `pulse-news.v1.json` file is signed and atomically replaced. A 45-minute freshness limit is enforced at read time. Scan reservations, source cooldowns and per-network last successful check timestamps survive worker restart on the same volume. The rollout assumes one worker process owns the mounted volume. The worker uses its existing signing key and publication/queue configuration and supports `ARC_PULSE_NEWS_ENABLED=0` as an opt-out. No environment settings are changed by this draft.

The scanner bounds each source to six HTTP operations and eight candidates, each response to 2 MiB, and the scan to a 30-second deadline. Each article source checks at most five detail pages. HTTP 403 and 429 pause that host for at least one hour, and 503 pauses it for at least one cohort. `Retry-After` is honored within 24 hours. The public API reads a signed snapshot from the worker and coalesces those reads for 30 seconds. Its bounded on-demand fallback can only enqueue the same authenticated worker scan through the same persisted throttle. The browser rechecks the active tab every five minutes while visible, backs off availability failures, and clears expired signals even if a request is still pending.

Use `node scripts/probe-pulse-news.cjs` for a read-only probe and `node --test test/pulse-projects.test.js test/pulse-news-storage.test.js` for deterministic acceptance fixtures. The Pulse CI artifact records current source coverage, which slots were eligible, their evidence grade and limitations, status reasons, and measured HTTP request count. The browser suite exercises 1440, 800, 390 and 320 px, mobile controls, keyboard tabs, safe links, visibility-aware expiry and both legacy archive paths.
