# Pulse V4 research coverage and rollout

Pulse keeps three fixed categories and the current homepage and signed edition paths. The added badge files are original local SVGs. Text labels carry the accessible meaning of the icons. The live view labels weekly ARCY Take as weekly edition context.

V3 reached its configured feeds while Arc had no eligible result. Its source inventory omitted Circle's Arc Node releases and advisories, Ethereum's explicit mainnet roadmap windows, and Robinhood Chain's operator notices. Its discovery rejected some records before recording why, counted expired candidates as review-required, and used a single publication-age window without a separately labeled historical path. Several Arc blog articles are documentation or retrospective launch summaries. Their datelines cannot establish a new deployment. Robinhood newsroom coverage includes corporate and old material and does not substitute for chain-specific operator notices.

V4 discovers four additional publisher endpoints. The Ethereum roadmap adapter follows upgrade detail links from the official releases timeline and reads the mainnet target and the displayed update date separately from testnet milestones. A published quarter is tentative and expires at the end of the quarter. A missing, expired or contradictory target remains ineligible. Arc Node results prove a package was published. The sync notes do not establish which software is running on mainnet or what changed internally. Official status and advisory sources remain the only risk inputs. Liquidity changes, privileges and independently corroborated on-chain incidents need separate, reviewed evidence adapters.

Source diagnostics distinguish attempted, reachable, extracted, scoped, rejected, current eligible and rendered counts. Per-source state and last success persist, and cooldown skips count separately from attempts. Counts from a shared source describe that source's whole scan, so totals across networks overlap. The current snapshot expires after 45 minutes. Under full category coverage, a supported completed development up to 60 days old or a resolved report up to 30 days old can appear as historical context. A stale snapshot, lost coverage or expired future plan cannot be promoted by history. The ledger retains 54 events and 54 explicit lifecycle records for at most 60 days. Structured Arc maintenance terminal updates retire matching plans across scans. Automatic lifecycle linkage across ambiguous titles or publishers is intentionally excluded.

The worker keeps its 15-minute reservation, existing signing credentials and persistent volume. At most four host groups run at once, six HTTP operations per source, 2 MiB per response, 30 seconds per scan and zero additional RPC calls. Rate limit and service outage cooldowns follow the existing worker policy. Browser traffic reads the signed worker snapshot. It cannot start publisher requests apart from the existing throttled authenticated wake.

The V4 worker writes `pulse-news.v2.json` atomically and can read a valid V3 snapshot from `pulse-news.v1.json`. It leaves the V3 file untouched. The legacy worker route keeps serving the V3 file, and the V4 client requests `schema=2`. This also permits the V4 web client to read an older worker's signed V3 response during rollout. Restore the preceding worker and Vercel builds to roll back. The old worker can resume its existing file and refresh when due. Verify the exact Railway build and its signed, advancing snapshot before considering the rollout enabled. Neither worker reads nor writes the historical edition or on-chain files as part of this change.
